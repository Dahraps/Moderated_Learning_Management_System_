# Password storage and justification

This project uses OpenSSL `PKCS5_PBKDF2_HMAC` with SHA-256, 210,000 iterations, a 16-byte (128-bit) random salt generated by OpenSSL `RAND_bytes`, and a 32-byte derived key. `User.password_hash` contains a hexadecimal derived key, while `User.salt` contains a hexadecimal salt. Passwords are not stored in the database. Verification recomputes the key using the stored salt and compares equal-length results using OpenSSL `CRYPTO_memcmp`.

**Why OpenSSL?** It is a widely used, maintained cryptographic library providing vetted password-based key derivation and secure randomness. PBKDF2 is deliberately computationally expensive, unlike a single SHA-256 digest, and the per-user salt prevents identical passwords from producing identical hashes. CMake finds and links `OpenSSL::Crypto`.

**Security considerations:** Passwords currently remain visible during console entry; implement hidden input for a deployment. Existing stored hashes use the same format and are compatible. PBKDF2 is acceptable for this coursework; Argon2id is generally preferred for new deployments when an appropriate library is available. Iteration counts should be revisited as hardware changes. Keep SQLite files access-restricted and backed up securely.

**Tests:** `tests/test_password_security.cpp` checks salt size, distinct salts, distinct hashes, correct verification, wrong-password rejection, and malformed salt handling.
